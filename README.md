# URL 路由规则调试台

本地运行的 URL 路由规则编排与模拟调试工具（React + TypeScript + Vite）。
编排有序规则后，输入一个「方法 + URL」即可逐步追踪匹配过程：命中了哪条规则、
捕获了哪些路径参数、URL 如何变化、因何终止。

## 快速开始（Docker，单条命令）

```bash
docker compose up --build
```

启动后访问 **http://localhost:8080**

## 本地开发

```bash
npm install      # 安装依赖
npm run dev      # 开发服务器（默认 http://localhost:5173）
npm test         # 运行引擎单元测试（vitest）
npm run build    # 类型检查并产出静态文件到 dist/
npm run preview  # 预览构建产物
```

## 规则模型

每条规则按顺序包含以下条件与动作，**首条全部条件命中的规则生效**：

| 字段 | 说明 |
| --- | --- |
| `method` | `ANY` 或具体方法（`GET` / `POST` / `PUT` / `PATCH` / `DELETE` / `HEAD` / `OPTIONS`） |
| `host` | 精确主机（`example.com`）或通配子域（`*.example.com`，匹配任意层级子域但不含裸域）；`*` 匹配任意主机；忽略端口 |
| `pathTemplate` | 路径模板，按 `/` 分段：字面段精确比较，`:name` 段捕获为路径参数；留空或 `*` 匹配任意路径；忽略末尾斜杠差异，匹配不看查询串 |
| `query` | 查询参数条件数组，多条按 **AND（且）** 组合，为空表示任意查询串均可命中。每条条件：`name` 参数名（同一规则内不得重复）+ `op` 操作符——`exists`（参数出现即命中，含空值 `?x=`）、`not-exists`（参数完全不出现才命中）、`equals`（同名参数**任一值**等于 `value` 即命中，如 `?x=a&x=b` 命中 `x equals a`）。参数名与比较值按解码后的原文精确比较（区分大小写） |
| `action.type` | `rewrite`（重写后继续匹配）/ `redirect`（立即终止）/ `stop`（立即终止请求） |
| `action.target` | 重写 / 重定向目标，可引用路径参数（如 `/v2/users/:id`、`https://new.com/:id`）；以 `/` 开头替换路径，http(s) 绝对地址整体替换；目标不含 `?` 时保留原查询串 |
| `action.status` | 重定向状态码：`301` / `302` / `303` / `307` / `308` |

旧版本导出的规则 JSON 没有 `query` 字段，导入时自动按**空条件**（任意查询串均可命中）处理。

## 模拟语义

1. 从第一条规则开始查找首个命中（未启用的规则跳过）。
2. **重写**：应用目标后回到第 1 步，从第一条规则重新匹配。
3. **重定向 / 停止**：立即终止，不再评估后续规则。
4. 每步以浏览器 `URL` API 序列化后的「方法 + URL」作为状态键；
   状态重复即判定**循环**，执行超过 **20 步**判定**超限**——两者都不会给出成功结果。
5. 不再有任何规则命中时，以当前 URL 作为最终结果（成功终止）。

界面会逐步展示：命中的规则与条件明细、捕获的路径参数、URL 变化、
每步的状态键，以及最终终止原因。

## 断点调试（单步 / 继续）

除一次性跑完全程的「运行」外，调试台还支持**断点 + 单步**执行：

1. **设置断点**：点击规则卡片序号右侧的 **○**（再次点击取消，命中断点的规则显示为
   **●** 并以红色高亮）。断点只存在于**当前页面会话**（内存），不写入
   `localStorage`，刷新后清空。
2. **开始调试**：请求栏输入「方法 + URL」后点击「开始调试」（未设任何断点时按钮禁用）。
   引擎从第一条规则开始执行，在**即将执行首条带断点的命中规则前暂停**——此时该规则的
   动作**尚未执行**。暂停点会展示当前**方法、URL、命中的规则与已捕获的路径参数**，
   以及此前已经执行完的步骤轨迹。
3. **单步（⤼）**：执行当前暂停点的动作，然后**暂停在下一条实际命中规则前**
   （不管它有没有断点）；若之后不再有规则命中或动作是重定向 / 停止，则运行到终止。
4. **继续（⏵）**：从当前暂停点**运行到下一断点**；之后没有断点时一直运行到终止。
5. **重新开始调试 / 结束调试**：前者按当前规则、请求与断点从第一条规则重新开一场会话；
   后者放弃会话回到普通视图。普通「**运行**」按钮保持原行为——一次跑完全程，
   不做任何暂停（并结束进行中的调试会话）。

几点语义：

- **暂停不重置执行状态**：单步 / 继续跑在同一个执行生成器上，循环检测的「方法 + URL」
  已见状态与 **20 步上限**跨暂停累计保留——暂停再多次，该判循环、该超限时结果与
  一次「运行」完全一致。
- **规则或请求变化即作废**：调试暂停期间，只要规则表（含字段、顺序、启停、导入等）或
  请求方法 / URL 发生变化，会话立即标记为**已过期**，「单步 / 继续」禁用并提示
  「重新开始调试」；已运行到终止的结果不受影响（它引用的是会话开始时的规则快照）。
- **断点在会话开始时快照**：会话中途增删断点不会改变本次执行（既不会让旧规则突然
  暂停，也不会取消已暂停点），点击「重新开始调试」后新断点才生效。
- 启动调试后若直到终止都没有命中断点（例如没有任何规则命中、断点规则不可达），
  会直接给出最终结果，不产生暂停。

## 遮蔽诊断

规则表每次变更（增删、排序、字段、启停）都会即时重新分析全部**已启用**规则：
若某条规则的全部可匹配请求都被它**之前的某一条已启用规则**完全覆盖，
该规则会被标记为**「不可达」**，并在卡片上列出首个遮蔽它的规则及四项覆盖依据
（方法 / 主机 / 路径 / 查询条件各自的覆盖关系）。

覆盖判定与模拟语义严格一致：

- **方法**：`ANY` 覆盖任意方法，具体方法仅覆盖相同方法；
- **主机**：`*` 覆盖任意主机；`*.example.com` 只覆盖其至少一级子域
  （含更深层通配，如 `*.sub.example.com`），不覆盖裸域；
- **路径**：空值或 `*` 覆盖任意路径；具体模板按分段比较，参数段覆盖同位任意单段，
  字面段仅覆盖相同字面值；
- **查询条件**：上方规则的每条条件都要被下方规则的某条同名条件**蕴含**——
  「存在」被同名的「存在」或「值等于」蕴含，「不存在」仅被同名的「不存在」蕴含，
  「值等于 v」仅被同名同值的「值等于」蕴含；上方规则无查询条件时覆盖任意条件组合。

只报告**完整覆盖**——部分交集（例如主机相同但路径段数不同、或查询条件取值不同）不告警；
禁用规则不参与分析（既不遮蔽别人，也不被诊断）。
诊断是纯分析提示，**不改变模拟执行结果**。

## 访问样本覆盖审计

规则编辑区下方的「访问样本覆盖审计」面板用于回答另一个问题：**一批真实访问样本里，
每条规则被多少请求命中、执行了多少次，又有哪些请求谁都没命中 / 触发了循环？**

用法：

1. 在文本框中粘贴多行样本，每行一条「`METHOD URL`」（方法大小写不敏感，空白分隔，
   空行自动跳过）。面板预置了一组示例样本，可直接试跑。
2. 点击「批量运行」：面板复用与单条模拟**完全相同的 simulate 语义**逐条运行，
   并按规则汇总：
   - **命中请求数**：至少命中过该规则一次的不同样本数——同一请求因重写绕回
     重复命中同一条规则时，请求数**只计一次**；
   - **执行次数**：该规则在全部样本轨迹中的累计命中步数，重复命中**累加**。
3. **点击任意规则行**可展开命中它的样本：每条样本显示行号、方法 + URL、
   在轨迹中第几步命中（重写绕回时可能有多步）及对应步骤明细。
4. 面板下方分组列出：**未命中任何规则**（直接放行）、**循环**、**超限**（超过 20 步）、
   **非法输入**（行格式有误或 URL 无法解析）以及**规则目标无法解析**的样本；
   每条也可展开查看完整轨迹与终止原因。

0 命中的规则（含已停用规则）仍会出现在清单中，以虚线 / 删除线样式标出，
方便发现没有样本覆盖或已停用的规则。

运行后只要**规则表或样本内容发生变化**，上次结果立即标记为**已过期**并提示重新运行。
样本文本与最近一次审计结果只保存在**当前页面会话**（内存），不写入 `localStorage`，
刷新页面即清空。

## 规则回归对比

页面底部的「规则回归对比」面板用于回答一个问题：**继续编辑规则后，已有请求的行为变了吗？**

用法：

1. **冻结基线**：点击「冻结当前规则为基线」，把当前规则表的**深拷贝快照**保存为基线
   （之后的任何编辑都不会影响基线；可随时「重新冻结基线」或「清除基线」）。
2. **维护用例**：添加若干条「方法 + URL」用例。
3. **运行回归**：点击「运行回归」，面板用同一个 simulate 引擎分别运行
   **基线规则**与**当前规则**，逐用例对比。

是否变化的判定只看**终止类型及其可观察结果**，不比较原因文案：

| 终止类型 | 比较内容 |
| --- | --- |
| `final` | `finalUrl` |
| `redirect` | 状态码 + `Location` |
| `stopped` | 仅终止类型 |
| 失败（`loop` / `max-steps` / `invalid-url` / `invalid-target`） | 仅失败类型 |

每条用例并排展示基线 / 当前两份结果；**有变化**的用例可展开两侧轨迹，
面板按 `rule.id`、`urlBefore` 与动作结果定位**首个差异步**并高亮；
两侧轨迹长度不同时，会标出多出的步骤与「轨迹在此结束」的位置。
运行后再修改规则、基线或用例，旧结果会提示已过期，需重新运行。

基线与用例保存在浏览器 `localStorage`（独立于规则表的存储键
`url-route-debugger.regression.v1`），刷新不丢失；数据损坏时回退为空，
不影响规则表。

## 规则编辑的撤销 / 重做

规则编辑器内置操作历史，工具栏的「↶ 撤销 / ↷ 重做」按钮会根据是否还有可撤销、
可重做步骤自动启用 / 禁用，也支持快捷键：

| 操作 | 快捷键（Windows / Linux） | 快捷键（macOS） |
| --- | --- | --- |
| 撤销 | `Ctrl+Z` | `⌘Z` |
| 重做 | `Ctrl+Shift+Z` | `⌘⇧Z` |

进入历史的操作包括：**新增规则、删除规则、上移 / 下移排序、启用 / 停用、
字段修改（下拉选择即时记录）、导入 JSON、载入示例与清空**。

历史记录的粒度：

- **文本输入框**（规则名称、主机、路径模板、动作目标）中，从**获得焦点到失焦**
  的一段连续输入（含输入法组词、框内原生撤销）**合并为一步**；失焦后一次撤销即可
  回到编辑前。焦点停留在输入框、文本域、下拉框等可编辑控件中时，`Ctrl/Cmd+Z`
  仍走**浏览器原生编辑行为**，不会触发全局撤销。
- 撤销之后只要再产生新的编辑，**重做分支立即丢弃**，无法沿旧分支重做。
- 撤销 / 重做恢复的是**完整规则表快照**，并会同时**清空当前模拟轨迹**
  （旧轨迹引用的是历史快照中的规则）；规则回归面板沿用既有的「结果可能已过期」
  提示，规则变化后重新运行即可。

历史只存在于**当前页面会话**（内存），不会写入 `localStorage`；刷新页面后仍从
现有的 `url-route-debugger.rules.v1` 恢复当前规则，历史栈从空开始。
通过「加密分享」链接确认导入另一份规则表时，规则整体替换，撤销 / 重做分支一并清空。

## 规则 JSON 导入 / 导出

- **导出 JSON**：将当前规则表下载为 `url-rules.json`。
- **导入 JSON**：选择 JSON 文件整体替换当前规则表，导入前会逐条校验并给出中文错误提示。
- 规则同时自动保存在浏览器 `localStorage`，刷新页面不丢失。

规则 JSON 示例：

```json
[
  {
    "id": "r1",
    "name": "API v1 → v2 重写",
    "enabled": true,
    "method": "ANY",
    "host": "api.example.com",
    "pathTemplate": "/v1/users/:id",
    "query": [],
    "action": { "type": "rewrite", "target": "/v2/users/:id", "status": 302 }
  },
  {
    "id": "r1-gray",
    "name": "灰度查询 env=canary 走灰度站",
    "enabled": true,
    "method": "ANY",
    "host": "api.example.com",
    "pathTemplate": "/internal/users/:id",
    "query": [{ "name": "env", "op": "equals", "value": "canary" }],
    "action": {
      "type": "rewrite",
      "target": "https://canary.example.com/users/:id",
      "status": 302
    }
  },
  {
    "id": "r2",
    "name": "旧博客 301",
    "enabled": true,
    "method": "GET",
    "host": "blog.example.com",
    "pathTemplate": "/posts/:slug",
    "query": [],
    "action": {
      "type": "redirect",
      "target": "https://www.example.com/blog/:slug",
      "status": 301
    }
  },
  {
    "id": "r3",
    "name": "后台禁止访问",
    "enabled": true,
    "method": "ANY",
    "host": "internal.example.com",
    "pathTemplate": "/admin/:token",
    "query": [],
    "action": { "type": "stop", "target": "", "status": 302 }
  }
]
```

`query` 可省略（等价于空数组）；同一规则内参数名重复会在导入时报
「第 N 条规则的查询条件存在重复参数名」定位错误。

## 导出可执行路由器

点击规则表工具栏的「导出路由器」，可把当前**已启用**规则打包为单个
`route-bundle.mjs`——自包含、零依赖（不引用项目源码与任何第三方包），
对话框内提供代码预览、复制与下载。若某条已启用规则不合法（空主机、空目标、
非法重定向状态码、无名参数段、查询条件参数名为空或重复等），对话框会逐条列出
「第 N 条规则」及原因，并阻止复制与下载，修正后即可导出。

生成物与调试台使用同一套语义：首条命中生效、重写后从第一条规则重新匹配、
路径参数捕获替换、查询参数条件（存在 / 不存在 / 值等于，AND 组合）、
以「方法 + URL」检测循环、最多 20 步。

**命令行运行（Node 20+）**：

```bash
node route-bundle.mjs GET 'http://api.example.com/v1/users/42?debug=1'
```

输出统一 JSON，包含终止类型（`status`）、最终 URL 或重定向
（`finalUrl` / `redirectLocation` + `redirectStatus`）与完整步骤（`steps`）：

```json
{
  "status": "final",
  "ok": true,
  "steps": [
    { "n": 1, "method": "GET", "urlBefore": "http://api.example.com/v1/users/42?debug=1", "urlAfter": "http://api.example.com/v2/users/42?debug=1" },
    { "n": 2, "method": "GET", "urlBefore": "http://api.example.com/v2/users/42?debug=1", "urlAfter": "http://api.example.com/internal/users/42?debug=1" }
  ],
  "reason": "没有更多规则命中，以当前 URL 作为最终结果",
  "finalUrl": "http://api.example.com/internal/users/42?debug=1"
}
```

结果为失败（`loop` / `max-steps` / `invalid-url` / `invalid-target`）时进程退出码为 1，
便于脚本判断；缺少参数时打印用法并以退出码 1 结束。

**作为模块调用**：

```js
import { route } from './route-bundle.mjs';

const result = route('GET', 'http://api.example.com/v1/users/42?debug=1');
console.log(result.status, result.finalUrl);
```

## 加密分享

点击规则表工具栏的「加密分享」，设置并确认口令后，可把当前**规则表、请求方法和 URL**
生成一条可复制的链接（密文写在 `#s=` hash 中），全程仅在浏览器端完成，没有任何服务端请求：

- 口令经 **PBKDF2-SHA-256**（随机 16 字节盐、**150000** 次迭代）派生 **256 位**密钥；
- 载荷以 **AES-GCM**（随机 12 字节 IV）加密，GCM 同时保证机密性与完整性；
- 链接中依次包含版本号、盐、IV 与密文（含认证标签），整体做 **base64url** 编码；
- **口令不会进入链接，也不会写入 localStorage**，只在加 / 解密瞬间存在于内存；
  请通过独立的安全渠道把口令告知接收方。

打开分享链接时，页面**只显示口令输入框**。解密成功后会复用 `validateRules` 校验规则表、
并再次校验请求方法与 URL，然后展示预览；**由接收方确认后**才整体替换当前规则表、方法、URL，
并清空旧的执行轨迹。以下情况都不会改变当前状态：口令错误、密文被篡改、版本不支持、
内容校验失败，或用户取消导入。成功导入后地址栏中的 hash 会被移除。

> 提示：加解密依赖浏览器 Web Crypto API，需在安全上下文（`https://` 或 `localhost`）下使用。

## 项目结构

```
src/
├── engine.ts        # 匹配与模拟引擎（主机/路径/查询条件匹配、参数替换、循环检测）；
│                    #   runSimulation 生成器在每条命中规则的动作执行前 yield，
│                    #   simulate 与断点调试共用同一核心，暂停不重置执行状态
```
